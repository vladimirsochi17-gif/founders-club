# Запуск на другом компьютере

## Быстрый запуск

1. Установите и запустите Docker Desktop (Windows/macOS) либо Docker Engine с Compose (Linux).
2. Склонируйте репозиторий либо скачайте GitHub → Code → Download ZIP и распакуйте.
3. В терминале перейдите в папку с `docker-compose.yml` и выполните:

```sh
docker compose up -d --build
```

4. Откройте http://localhost:8787. Первый запуск скачивает образы и зависимости.
5. Локальный демонстрационный вход: `demo-owner@founders.local`, код `123456`. Можно зарегистрировать отдельный тестовый аккаунт с тем же локальным кодом. Реальная отправка писем для этого режима не нужна.

```sh
docker compose ps
docker compose logs --tail=100 app
```

Проверка API: http://localhost:8787/api/health — ожидается `status: ok`, `database: ok`.

## Что включено

- Исходники интерфейса и API, статические изображения/иконки/шрифты, lock-файл зависимостей.
- Миграции PostgreSQL и демонстрационные данные, применяемые при старте.
- Docker-конфигурация, автоматические тесты, инструкции и чеклисты.
- Код интеграции с Supabase и шаблон `.env.supabase.example`; для локального Docker-запуска он не нужен.

Не включены реальные пароли, ключи Supabase/VPS, `.env` с секретами, локальные базы, пользовательские загрузки, `node_modules`, собранный `dist` и журналы. Зависимости и сборка восстанавливаются автоматически из исходников.

База данных и пользовательские файлы предыдущего компьютера не являются частью исходного кода. На новом компьютере создаётся чистая локальная среда. Для переноса существующих данных нужен отдельный backup/restore; не публикуйте дамп в GitHub.

## Хранение данных

Данные переживают перезапуск контейнеров и `docker compose down`. Не добавляйте `-v` к команде остановки: этот параметр удаляет тома вместе с данными.

Локальные порты: приложение `8787`, PostgreSQL `54329`, оба привязаны к `127.0.0.1`. Не используйте эту конфигурацию как публичный production-сервер: в ней есть демонстрационные учётные записи, фиксированный тестовый код и mock-платежи.

## Текущий статус и ограничения

- 23 октября 2026: проверка типов, 33 автоматических теста и сборка прошли перед подготовкой переноса.
- Оплата — тестовая имитация; в production реальные платежи отключены до подключения провайдера.
- SMTP, Telegram-приглашения, реальные архивы библиотеки и юридические настройки требуют отдельной настройки.
- Часть административных, редакционных и командных форм остаётся демонстрационной. Полный workflow правок опубликованных проектов не завершён.
- Некоторые аналитические экраны, промо-календарь, фильтры рейтинга и вкладки публичных профилей используют демонстрационные/неполные данные. Наличие экрана не означает завершённую серверную реализацию.
- Подключение к Supabase PostgreSQL с проверкой сертификата и создание закрытого Storage bucket проверены. Полный удалённый сценарий с загрузкой изображения не завершён: во время проверки обрыв соединения PostgreSQL привёл к падению API; обработка этого случая требует исправления перед публичным запуском.
- VPS не настроен и публичный адрес приложения не запущен. Перенос исходников на GitHub сам по себе не публикует работающий сайт.

Секреты, переданные ранее в переписке, не входят в репозиторий. Перед дальнейшим внешним использованием смените пароль БД/VPS и отзовите старый серверный ключ Supabase.
